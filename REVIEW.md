# Отчёт ревьюера: корутины для e2k

Объект ревью: архив `co_e2k.zip` (`coro_e2k.S`, `test_coro.S`,
`qemu-e2k-fixes.patch`, сопроводительный документ). Цель — проверить
заявленный результат натурным экспериментом, оценить пригодность решения и
довести его до состояния, годного для эмулятора и для железа.
Итог доработки — этот репозиторий.

## 1. Стенд

Docker `ubuntu:24.04` (arm64), OpenE2K binutils `binutils-mcst-2.41`
(as/ld 2.41.0‑29.023), OpenE2K qemu‑e2k ветка `e2k`, HEAD `ebc4bbd` —
хеши блобов `helper_int.c`/`translate.c` в патче автора совпадают с этим
коммитом, т.е. автор работал ровно на нём. Собраны три эмулятора:
**A** — оба патча автора, **B** — только `helper_int.c`, **C** — без патчей.

## 2. Воспроизведение исходного результата

| qemu | код автора | код автора + `ct %ctpr3` |
|---|---|---|
| A (оба патча) | вывод как в документе, exit 0, 3/3 прогона | то же |
| B (только `helper_int.c`) | зацикливание: `return` «проваливается», `main: start` бесконечно | **работает** |
| C (без патчей) | зацикливание | SIGILL на первом `rwd %psp.hi` |

Заявленный результат воспроизводится. Но матрица показывает, что из трёх
«дефектов qemu» в документе подтверждается один.

## 3. Разбор утверждений документа

**«`return %ctpr3` без SS‑слога не транслируется в передачу управления» —
не дефект эмулятора.** В e2k `return` (CS0‑слог) лишь готовит `%ctpr3`;
переход выполняет отдельная инструкция `ct %ctpr3` (SS‑слог). Так генерирует
lcc, так реализовано в qemu (`helper_prep_return` против `helper_return`),
мнемоника `ct` есть в gas (`opcodes/e2k-opc.c`). В коде автора `ct`
отсутствует во всех четырёх местах (подтверждено objdump). Патч
`translate.c` заставляет `return` прыгать сам — он маскирует ошибку кода и
**ломает семантику эмулятора** для любого кода, где между `return` и `ct`
стоят команды, т.е. для штатных бинарников lcc. Патч отвергнут.

**«Для безусловной передачи требуется ненулевой `cond_type`» — следствие
предыдущего.** `cond_type = 0` означает «never»; при `ct %ctpr3` ассемблер
ставит «always».

**«Запись в стековые регистры запрещена в user‑mode» — верно.** PSP/PCSP
привилегированы; на железе их переключает ядро (e2k‑syscalls
`makecontext`/`swapcontext` 370/371, которыми пользуется glibc), qemu
linux‑user их не реализует (`do_swapcontext: TODO`). Разрешить запись в
эмуляторе — оправданная замена отсутствующей поддержки ядра. Патч принят
в урезанном виде (`tools/qemu-e2k-user-hwstacks.patch`).

Вывод по документу: аргумент «сломанный инструментарий» следует свести к
одному пункту; общий тезис — что решение выведено из семантики
архитектуры, а не скопировано, — экспериментом не опровергается.

## 4. Замечания к исходному коду

| # | Серьёзность | Замечание | Как проявлялось |
|---|---|---|---|
| 1 | критично | `return %ctpr3` без `ct %ctpr3` (×4) | работает только с вредным патчем транслятора |
| 2 | критично для железа | нет `flushr`/`flushc` перед чтением PSP/PCSP | в qemu no‑op; на железе регистровый файл не пролит — контекст неполный |
| 3 | существенно | стек данных развёрнут: SP ставится в **низ** области, комментарий «растёт вверх»; `getsp +N` в тесте освобождает, а не выделяет | штатное выделение кадра `getsp −N` уводит SP ниже `area` (тест: «frame below area», затем SIGSEGV); тест автора течёт по 32 байта на итерацию, 4000 итераций — SIGSEGV |
| 4 | существенно | `CR1_LO_FABRIC` ставит `cr1.psr = PSR_PM` | корутина исполняется «в привилегированном режиме»; в qemu это заодно делало `rwd` разрешённым после первого входа; на железе некорректно |
| 5 | существенно | `coro_finish` и `return` из `entry` не покрыты тестом (main возобновляет каждую корутину ровно 3 раза) | путь завершения не проверялся автором (при проверке — работал) |
| 6 | существенно | `entry` получает параметры не по ABI (через bootstrap‑блок под SP) | нельзя вызывать функции, скомпилированные lcc |
| 7 | умеренно | в `coro_finish` при повторном возобновлении — `exit_group(2)` из библиотеки | библиотека завершает процесс |
| 8 | умеренно | `coro_transfer` → `__coro_switch` вложенным вызовом ради «нормализации окна» | лишний spill/fill; при окне вызывающего > 64 регистров `setwd 0x20` даёт SIGILL (окно нельзя уменьшать ниже области параметров — проверено) |
| 9 | мелочи | нет проверки аргументов `coro_init`; `cuir` = 0; `%g` не сохраняются (для кооперативных корутин допустимо) | — |

## 5. Что сделано в доработке

* `return` + `ct`; `flushr`/`flushc` перед сохранением.
* Стек данных растёт вниз от `sbr`; `own_ctx` — на вершине (внутри `ussz`
  фабрикованной записи), никакого блока под SP.
* Одна фабрикованная chain‑запись на трамплин; `entry(arg)` вызывается по
  ABI косвенным `movtd`→`%ctpr1`+`call` (в `ctpr` нужен тег DISP в битах 54–56 —
  проверено). Завершение: флаг + переход в `ret_ctx`; повторное
  возобновление — снова в `ret_ctx`, без выхода из процесса.
* `psr`/`cuir` в фабрикованной записи наследуются от создателя (`rrd`).
* `coro_transfer` — одна функция, окно расширяется до максимума (`wsz = 0x70`);
  вложенный `__coro_switch` убран.
* `coro_init` проверяет аргументы (NULL, выравнивание 4 КиБ, минимум),
  возвращает −1/0; добавлен `coro_finished`.
* C‑API `include/coro.h`; второй бэкенд `src/coro_ucontext.c` для
  user‑space на железе.
* Патч qemu сведён к `helper_int.c`.
* Вторая итерация: `coro_init_ex` с атрибутами (размеры PS/PCS,
  guard‑страницы `PROT_NONE` через `mprotect` под стеком данных и над PS/PCS;
  в UCONTEXT — под стеком, размер guard = страница ОС), `coro_destroy`
  (снимает guard, инвалидирует ctx, на e2k/UCONTEXT — `freecontext`).

## 6. Верификация доработанного решения

DIRECT под qemu‑B (только `helper_int.c`): 8 тестов PASS —
`basic`, `finish`, `stress` (100 000 раундов × 2, кадр проверяется через yield;
0,1 с), `nested` (yield из глубины 3 с живыми регистрами и кадрами на каждом
уровне), `frame` (SP на вершине, кадр 2 КиБ внутри области), `init_errors`,
`attrs` (геометрия с заданными размерами, рекурсия 200 уровней при PCS 8 КиБ,
`coro_destroy` снимает guard), `guard_fault` (запись в guard — SIGSEGV,
exit 139; контрольная мутация без флага — процесс выживает).
Под qemu‑A — тот же результат; под qemu‑C — SIGILL, ожидаемо.
UCONTEXT: `tests/test_coro.c` — те же сценарии — PASS на Linux/arm64 и macOS.
Проверка умеет падать: при порче `.expected` `make check` возвращает ошибку;
мутации библиотеки (убрать `ct`, не сохранять `pcsp.hi`, не выставлять флаг)
ловятся тестами. Мутация «не восстанавливать `usd.lo`» не ловится — и не
должна: `return` восстанавливает USD из `sbr` и `cr1.ussz` сам, явная запись
избыточна и оставлена ради самодостаточности контекста.
Стенд воспроизводится из `tools/Dockerfile`.

## 7. Ограничения и что осталось

* На железе ничего не проверялось — нет доступа к машине. Для DIRECT на
  железе нужно подтвердить: достаточность `flushr`/`flushc`, допустимость
  `cr1.psr` из фабрикованной записи, отсутствие требования `wait` между
  записью PCSP и `ct`. Для UCONTEXT — просто собрать lcc и прогнать
  `tests/test_coro.c`.
* Единого бинарника для эмулятора и user‑space железа не существует по
  устройству архитектуры; выбор бэкенда — на этапе сборки.
* UCONTEXT на железе — системный вызов на каждое переключение; для
  высокочастотных корутин это может быть неприемлемо, нужен замер на машине.
* `freecontext` в UCONTEXT — слабая ссылка на непроверенный символ glibc e2k;
  без него `coro_destroy` оставит утечку аппаратных стеков в ядре.
* Не сохраняются FP‑состояние сверх того, что уносят chain‑записи, и
  `%g`‑регистры. Guard‑страницы требуют ОС с `mprotect`: в привилегированном
  окружении на железе флаг `CORO_ATTR_GUARD` неприменим.
* Guard над PS/PCS в qemu не срабатывает: linux‑user «расширяет» стек через
  `mremap` раньше, чем запись доходит до guard‑страницы (проверено бесконечной
  рекурсией). Эффективность guard над PS/PCS — только на железе, не проверена.
* Косвенный вызов `entry` через `movtd`→`%ctpr1` с явным тегом DISP проверен
  только в qemu — первое, что проверять на железе.
